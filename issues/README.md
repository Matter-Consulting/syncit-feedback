# Issues: bugs

One file per bug a maintainer has looked at, named after its GitHub issue:
`0012-push-to-etabs-stops-on-a-new-project.md`. Newest last, so the folder reads as the
history.

A file is written when the bug is decided (fixed, planned, a question back, or declined) and
updated when that changes. Its front matter: `id` (the file's name), `issue` (the GitHub
number), `kind: bug`, `area`, `title`, `version` (the app version it was reported on), `date`,
`status` (open, planned, waiting, fixed, answered or declined), `closed`, `resolution` (the
commit that fixed it, or where it was planned). Then the report, the decision, the links.
The whole shape, and who writes it: [`../TRIAGE.md`](../TRIAGE.md).

To report a bug: [`../README.md`](../README.md).
