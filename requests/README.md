# Requests: features and changes

One file per feature request a maintainer has looked at, named after its GitHub issue:
`0014-copy-a-column-type-to-a-new-mark.md`. Newest last, so the folder reads as the history.

A file is written when the request is decided (built, planned, a question back, or declined)
and updated when that changes. Its front matter: `id` (the file's name), `issue` (the GitHub
number), `kind: request`, `area`, `title`, `version` (the app version it was asked on),
`date`, `status` (open, planned, waiting, fixed, answered or declined), `closed`, `resolution`
(the commit that built it, the TODO heading it was planned under, or why it was declined).
Then the request, the decision, the links. The whole shape, and who writes it:
[`../TRIAGE.md`](../TRIAGE.md).

To ask for a feature: [`../README.md`](../README.md).
